## 1. 状态模型

```
Board = { objs: Obj[], sections: Sec[], edges: EdgeData[] }
Obj   = { id, kind: card|text|media, x, y, w, h, folded?, color?, sectionId?, … }
```

- 一切都是**绝对坐标对象**，初始位置由 Stage 2 的瀑布流算一次，之后由拖拽改写。
- 历史 = 快照栈（最多 50 步），`run(fn)` 提交前压栈；撤销/重做直接换整个快照。
- 拖拽过程中不写状态：只把 `translate3d(dx,dy)` 挂在被拖对象上，松手时一次提交。
  好处：拖动跟手（不触发 React 重排），撤销只记一步。

## 5. 没做好 / 下一步

1. **30 秒录屏对比没做**：参数和数值都有了（§6），但"三轮前后对比"要真录屏，环境里没有录制工具。
2. **拖拽没有边界约束**：可以把卡拖到负坐标，画布会跟着长。
3. **吸附只看对象边与中线**，等距分布提示（相邻间距相等）还没做。
4. **撤销不还原选中态**：撤销后选中集合可能指向已删除对象。

## 6. 手感基线（4.12）

### 6.1 参数

| 项 | 值 | 在哪 |
| --- | --- | --- |
| 跟随 | **1:1**，无缓动 | `startDrag` 里只乘 `1 / zoom`，不加阻尼 |
| 拖动渲染 | `translate3d`，不触发重排 | `.obj { transform }` |
| 提交时机 | **松手提交一次**，整个拖动过程只有一次 `run()` | `onPointerUp` |
| 吸附阈值 | **6 屏幕像素**，按缩放换算成世界坐标 | `snapMove(board, ids, dx, dy, zoom)` |
| 吸附对象 | 其他卡/分区的 左、中、右、上、中、下 | `board-state.ts` |
| 吸附提示 | 1px 蓝色虚线，`3 3` 虚线，出现在对齐位置 | C17 |
| 松手回弹 | **无**。吸附结果直接作为最终位置 | — |
| 缩放锚点 | 指针位置（`⌘滚轮`） | C10 |
| 缩放范围 | 0.1–4.0，步进按钮 ×1.25 | C20 |

### 6.2 测法（可复现）

```bash
cd app
# 逐帧偏差：拖一张卡 20 帧，记录每帧「实际位置 − 理论位置」
node scripts/probe.mjs "http://localhost:5173/#/s02?theme=light&fit=1" "<见下>"
```

探针做的事：`pointerdown` 在卡片上 → 连发 20 次 `pointermove`（每次 +9px 横 / +7px 纵）→
每次 `await requestAnimationFrame()` 后读 `getBoundingClientRect()` → 与"起点 + 累计位移"相减。

### 6.3 实测（2026-10-22，无头 Chrome，DPR 1）

| 指标 | 值 | 判读 |
| --- | --- | --- |
| 逐帧偏差范围 | **−3.43 ~ +3.91 px** | 全部小于吸附阈值 6px ⇒ 是吸附修正，不是滞后 |
| 首帧偏差 / 末帧偏差 | 0.81 / 1.43 px | 不随帧数增长 ⇒ **没有累积延迟** |
| 单帧从 pointermove 到 DOM 更新 | 中位 **17.0 ms**、P90 18.1 ms、最大 21.7 ms | ≈ 1 帧（60Hz 为 16.7ms）⇒ 无可见滞后 |
| 松手后位置误差 | dx −3.4 px、dy −0.1 px | 即吸附把它拉到了对齐线 ⇒ **一次到位** |

### 6.4 结论与未做

- 「拖动跟手：无可见滞后」——**成立**，逐帧 ≤ 1 帧。
- 「吸附一次到位（≥ 90% 无需微调）」——**间接成立**：松手位置误差恒等于吸附修正量，说明落点已被吸附接管；但没做真人微调率统计。
- 未做：30 秒操作录屏的前后三轮对比（4.12 原文要求），环境无录屏工具，需在真机上补。
