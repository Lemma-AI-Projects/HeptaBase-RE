# 画布交互改造 · 计划

> 目标：白板的手感做到 Figma / Obsidian Canvas 的水平。
> 结论先说：**底层的引擎和新手操作这两件事都不行**。滚轮缩放 30 次只生效 1 次；连线只能改，不能新建。

---

## 0. 实测（不是感觉）

### 0.1 拖动与缩放

| 项 | 实测 | 应该 |
| --- | --- | --- |
| 连发 30 次 `⌘滚轮` | 缩放 1.000 → **1.016**（期望 1.616），**塌缩成 1 次** | 30 次都生效 |
| 150 张卡拖动 40 帧 | 中位 16.6ms，**P95 43.1ms，最慢 49.1ms** | P95 ≤ 20ms |
| 33 张卡拖动 | 中位 17.0ms，逐帧偏差 ≤ 4.8px | 已合格 |
| 双击空白 | 卡数 33 → 33，**什么都没发生** | 新建一张卡 |
| 拖到屏幕边缘 | 不滚动，卡被窗外挡住 | 画布自动平移 |
| 方向键 | 没有绑定 | 1px / Shift 10px |
| 卡片改大小 | 没有手柄 | 有 |

**滚轮为什么塌缩**：`C10` 的 `onWheel` 用渲染时闭包里的 `viewport.zoom` 算新值。两次渲染之间来 10 个事件，
10 个都基于同一个旧值，最后只剩 1 个。触控板捏合一次发 60–120 个事件，所以手感是"顿一下才动"。
而且 `useEffect` 依赖 `viewport`，**每次缩放都解绑重绑一次监听器**。

**拖动为什么掉帧**：`S02` 的 pointermove effect 依赖 `interaction`，每移动一次就重绑监听 + 重渲染全部卡片。

### 0.2 连线（用户点名的）

| 项 | 实测 | 应该 |
| --- | --- | --- |
| 从卡片拉一条新线 | **卡片上一个锚点都没有（0 个）**，只能在已有的 6 条上改 | 悬停卡片边缘出现 4 个锚点，拖出来就是新线 |
| 端点 | 10×10 px 的小圆点，**选中后才出现** | 12px 圆点 + 24px 命中区，一直显示 |
| 拖端点到空白 | 静默吸到最近对象，或原样回弹，**没有提示** | 空白处松手 = 新建一张卡并连上（Obsidian 行为） |
| 拖端点过程中 | 目标卡不高亮，不知道会连到哪 | 目标卡描边高亮 + 候选锚点 |
| 线标签 | 压在卡片下面，点不到（elementFromPoint 命中的是别的东西） | 标签单独一层，永远在线之上 |
| 42% 缩放 | 命中区 14 × 0.42 = **5.9px**，几乎点不中 | 命中区按 16 / zoom 补偿，屏幕上恒定 16px |
| 箭头 | 画了箭头 | 参考图没有箭头 |
| 线的弯曲 | 只能在工具条里切"曲线/直角" | 拖中点直接拖弯（FigJam） |

### 0.3 其他子功能

| 项 | 实测 | 问题 |
| --- | --- | --- |
| 右键菜单 | 能用（33 → 34 张卡） | 菜单上写着 `N` `S` 快捷键，但这两个键**没绑** |
| 双击卡片 | 跳到 `/s03` 整页 | 离开画布，回来要重新定位；Obsidian 是就地展开编辑 |
| 分区 | 能拖入、能折叠 | 只有一层，不能嵌套 |
| 撤销 | 能用 | 不还原选中态，撤销后可能选着已删除的对象 |
| 拖到负坐标 | 允许 | 画布边界跟着外扩，小地图被拉扁 |
| 框选 | 能用 | 拖动中不显示"已选中 N 个" |
| 小地图 | 能用 | 点击跳转是中心对齐，点角落会跳过头 |

## 2. 四期

### P0 · 引擎（外观不动，手感立刻变）

| # | 改什么 | 文件 |
| --- | --- | --- |
| P0-1 | 视口放进 `ref`，`onWheel` 读 ref；监听器只在挂载时绑一次 | `C10-CanvasViewport` |
| P0-2 | 指针移动累积到一个 rAF，**每帧最多一次 setState**；`interaction` 也进 ref | `S02-Whiteboard` |
| P0-3 | `C11` 用 `memo` 包住，props 不变不重渲染 | `C11-CardNode` |
| P0-4 | 缩放范围 0.05–8 | `tokens` |

**验收**：30 次 `⌘滚轮` 后缩放比 = 1.61 ± 0.02；150 卡拖动 P95 ≤ 20ms。

### P1 · 连线（点名要的）

| # | 改什么 | 细节 |
| --- | --- | --- |
| P1-1 | 卡片/分区悬停出 4 个锚点 | 上右下左各一个 10px 圆点，悬停才显形；按住拖出 = 新线 |
| P1-2 | 拖端点时目标高亮 | 鼠标下的卡描边 2px 强调色；候选锚点放大 |
| P1-3 | 拖到空白松手 = 新建卡并连上 | 新卡落点即松手点，自动接最近的边，**一步撤销** |
| P1-4 | 端点命中区放大 | 可见 12px，命中 24px；线命中区 = 16 / zoom（屏幕恒定） |
| P1-5 | 标签单独一层 | 线在卡下，标签在卡上；双击线就地改字 |
| P1-6 | 拖中点弯折 | 拖出控制点，曲线跟着变；双击中点复位 |
| P1-7 | 默认无箭头 | 方向只在工具条里显式打开才画 |

**验收**：从 A1 拉一条到新位置，卡数 +1 且线数 +1；42% 缩放下点线中点能选中；标签不被任何卡盖住。

### P2 · 编辑能力

| # | 改什么 | 细节 |
| --- | --- | --- |
| P2-1 | 双击空白新建卡 | 卡落在双击点，直接进标题编辑 |
| P2-2 | 方向键微移 | 1px；`Shift` 10px；多选一起动；算一步撤销 |
| P2-3 | 卡片改大小 | 四角 + 四边；最小 120×80；内容按新宽度重排 |
| P2-4 | 拖到边缘自动平移 | 距边 48px 内开始，0→12px/帧线性 |
| P2-5 | `Shift+2` 缩放到选区 | 有选中套选区，没选中套全板 |
| P2-6 | 多选对齐 | 左/中/右、上/中/下、等距分布 |
| P2-7 | 双击卡片就地展开 | 不跳页，在卡内直接编辑，`Esc` 收起 |

**验收**：方向键 10 次右移卡 `x` +10；拖到边缘 2 秒位移 > 200px；改大小 10 次无错位。

### P3 · 观感

| # | 改什么 |
| --- | --- |
| P3-1 | 缩放过渡 120ms（只给按钮/快捷键，滚轮不加，会拖慢跟手） |
| P3-2 | 平移惯性，最长 400ms |
| P3-3 | 光标：空白 default / 空格 grab / 拖动 grabbing / 框选 crosshair / 手柄 resize |
| P3-4 | 拖动时被拖的卡阴影加深，其余降到 85% |
| P3-5 | 等距吸附提示（两段带数字的间距线） |
| P3-6 | 右键菜单补上 `N` `S` 的绑定，或去掉这两个标记 |

**验收**：`⌘0` 有 120ms 过渡；拖动时鼠标形状与状态一致。

## 4. 不做

旋转、矢量绘制、多人协同光标、触屏双指、分组（group）。

---

## 5. 依赖

```
P0-1 ─┬→ P0-2 ─┬→ P1-3（新建卡要复用指针管线）
      │        └→ P2-3（改大小要复用）
      └→ P2-4（auto-pan 读视口 ref）
P1-1/P1-2/P1-4 互相独立
P3 全部依赖 P0，否则动画会加重卡顿
```

**P0 一次做完再给人看**（单改一条感觉不出来）；P1 之后可以一条一条上。

---

## 6. 风险

| 风险 | 处理 |
| --- | --- |
| 状态挪进 ref 后 React 不重渲染 | 只把高频数值进 ref，选中集合仍走 state |
| 150 卡只改 transform 不够 | `memo` 包 C11 |
| auto-pan 与吸附打架 | auto-pan 时不显示吸附线 |
| 锚点与"双击打开卡片"冲突 | 锚点带 `data-anchor`，双击判定排除 |
| 标签提到卡之上后挡住点击 | 标签设 `pointer-events: none`，只有双击文本区域才接管 |

## 7. 落地进度（2026-10-22）

### P0 全部完成

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 30 次 `⌘滚轮` 的缩放比 | 1.016 | **1.616**（理论值 1.616） |
| 150 卡拖动 P95 | 43.1ms | **18.0ms** |
| 150 卡拖动最慢帧 | 49.1ms | **18.1ms** |
| 缩放范围 | 0.1–4 | 0.05–8 |

改法：
- `C10` 的视口以 `vpRef` 为准，`commit()` 先写 ref 再回调；wheel 监听只在挂载时绑一次。
- `S02` 的拖动位移改由 **CSS 变量 `--dx/--dy` + `data-dragging`** 驱动，pointermove 里只写 DOM，不 setState。
  吸附线也直接写一个独立 `<g>`，全程零重渲染。松手时用 ref 里的增量一次提交。
