# 03 · 后续 Stage 路线图（Stage 2 – 8）

> 每个 Stage 结束都交付一个**可运行、可点击**的版本 + 一份 2 页说明。
> 没有"最后一并交付"这种事：任何一版都可以叫停、可以改方向。
> 体量标记：S（小）/ M（中）/ L（大）/ XL（最难，需要反复调）。

**贯穿全阶段的三个常设任务**（不单独占阶段）：
- 参考图对照：每个新界面做完，立刻与 `references/` 里对应图并排看一次；

- 孤岛抽检：每阶段随机抽 3 个零件做孤岛测试。

## Stage 2 · 视觉语言（体量 L）

**目标**：把"看见的 HeptaBase"变成"可以复用的零件"，并固化为唯一来源。

**为什么在这里**：本次任务的第一优先级就是风格；而且所有后续界面都继承它，越晚做返工越多。同时，没有零件墙，Stage 3 的骨架只能靠即兴发挥。

**关键交付**：
1. **基准值表**：颜色（画布/卡片/描边/文字三级/强调/7 色卡板 + 暗色映射）、字号与行高（6 级）、间距（4px 网格，6 档）、圆角（3 档）、阴影（3 档）、动效（3 条曲线 + 3 个时长）。
2. **零件墙**：卡片（普通/折叠/悬停/选中/7 色）、分区、文本元素、连线（直线/曲线/双向/带标签）、左侧应用栏、标签条、右侧工具面板、按钮与图标按钮、输入框、标签胶囊（tag）、气泡菜单、浮层菜单、空态、滚动条。
3. **指纹对照页**：左边参考图、右边实现，13 条逐条打勾（这是这一阶段的"成绩单"）。
4. **暗色映射**：不是反色，而是重新给定一组明度关系（卡片在暗色下靠"更亮的表面"而不是阴影来分层）。

**出口标准**：
- 截图指纹 13/13 通过（含暗色）；
- 三秒辨识测试 ≥ 90%（卡片 / 分区 / 文本 / 浮层 四类）；
- 零件墙里任意两张卡片，缩放到 60% 仍能区分"折叠/展开/选中"三态；
- 圆角与描边在 1x 与 2x 屏幕下都不出现"脏边"。

**风险**：过早抽象（做了 30 个用不上的零件）。**对策**：只做"Stage 3 第一屏真正会用到"的零件，其余留空位，随用随补。

## Stage 3 · 骨架与导航（体量 M）

**目标**：一个"还没有内容"的学习空间，看起来已经是个成熟产品。

**为什么在这里**：零件必须在真实信息密度下才被判断"对不对"；导航决定了后面每个功能的落点，改导航等于改所有界面。

**关键交付**：
- **左侧栏**：上半部应用区（Inbox / Journal / Whiteboard / Card Library / Tag，先做 5 个）、下半部标签系统（普通标签、置顶标签、标签分组、标签文件夹）；
- **顶部标签条**：彩色圆点 + 名称 + 右侧动作组（分享位、更多、图标组）；
- **右侧面板**：可开合、多工具切换（对话 / 卡片库 / 目录 / 信息 / 复习队列），面板切换不引起画布重排跳动；
- **⌘K 命令面板** + **⌘O 全局搜索**（带高级筛选条）；
- **右键菜单**、**快捷键总表**（可呼出）、**面包屑**、**多面板分屏**（分屏时可拖拽互传卡片）；
- **空态**：每个入口都有"下一步"而不是"暂无内容"。

**出口标准**：
- 零说明任务"找到我上周的一张卡，并打开它所在的另一块板"完成率 ≥ 80%；
- 键盘可达所有主要动作（不用鼠标完成一次完整导航）；
- 面板开合 10 次，画布内容不位移、不重排；
- 任意界面在 1280 宽下无横向滚动、无文字截断。

**风险**：壳子做太满、导航层级过深。**对策**：先只做 5 个应用入口；任何"再点一层"的设计都要在评审时被质询。

## Stage 4 · 画布与对象（体量 XL，最难）

**目标**：让"想清楚"这件事在画布上有手感。

**为什么在这里**：画布是 HeptaBase 范式的核心，也是所有学习动作的发生地。卡片没有画布只是笔记；而画布手感不行，用户会退回列表视图，整个范式失效。

**关键交付**：
- 无限画布：缩放 10%–400%、平移、双击空白新建、空格拖拽；
- 四种对象：卡片、文本、分区、图片（PDF 页作为图片对象的一种）；
- 连线：曲线/直角、双向/单向、带标签、可拖动控制点、箭头样式；
- 选择与批量：框选、Shift 加选、批量改色/移动/折叠/删除；
- 对齐与吸附：智能间距、等距提示线、分区自动容纳与自适应；
- 折叠/展开、聚焦模式（只显示选中对象及其邻居）、小地图；
- 左侧工具栏、对象右键菜单、缩放控件（百分比 + 加减 + 适配）。

**出口标准**：
- **手感三项**：拖动跟手（无可见滞后）、缩放无跳变、吸附一次到位（不出现"差 2px"）；
- 陌生用户 90 秒内完成"放两张卡 + 连一条线 + 框选改色"；
- 连续拖拽 20 次无"甩出去/粘住"；撤销 100% 覆盖破坏性动作；
- 一块 150 个对象的板，滚动与缩放仍然跟手（感知）。

**风险**：手感是黑箱，自测永远"感觉还行"。**对策**：先定手感基线（跟随系数、吸附阈值、惯性衰减），每次改动都用同一段 30 秒操作录像做前后对比，并请真人试。

## Stage 5 · 卡片与编辑器（体量 L）

**目标**：卡片里"写得进东西"，而且写的时候不打断思考。

**为什么在这里**：画布上的对象要能"长出内容"，否则整块板都是标题。阅读与标注（PDF/视频）也必须在这里完成，因为它是"采 → 读 → 抓"的前半段。

**关键交付**：
- 块编辑器：标题、有序/无序列表（可折叠）、待办、引用、代码、表格、图片、分割线、公式（简化）；
- `/` 斜杠菜单、`@` 提及卡片与块、回链面板（含块级回链）；
- 卡片信息栏：创建/修改时间、字数、标签、属性、出现在哪些板、提及了谁；
- PDF 卡：预置页图、文本层、划线/区域标注、标注浮动菜单、摘录成卡（自动带出处）；
- 视频卡：字幕列表、点字幕跳到时间点、摘录成卡；
- 卡片模板（3 个即可：读书笔记 / 概念卡 / 问题卡）。

**出口标准**：
- 从"在 PDF 里划线"到"板上出现一张带出处的卡"≤ 3 次操作；
- 连续写作 10 分钟不出现可感知卡顿；块级操作（移动/复制/折叠）不丢失选中态与光标；
- 编辑器内的排版与零件墙一致（字号行高完全一致，不允许"编辑器有自己的样式"）。

**风险**：编辑器是无底洞。**对策**：只实现 8 种块，其余用"占位块"呈现（视觉完整、行为提示"原型未实现"），绝不为此延期。

## Stage 6 · Learn Space 专有层（体量 L，差异化所在）

**目标**：让评审一眼看出"这不是 HeptaBase 换皮，而是学习空间"。

**为什么在这里**：差异层只有在基础设施（画布 + 卡片）已经顺手时才被感知为"更好"；太早做会被感知为"更复杂"。

**关键交付**：
1. **学习路径条**：一个主题拆成 4–6 个台阶（如"读 → 摘 → 连 → 讲给我听 → 复习"），当前台阶高亮，完成即前进；可折叠成一条细线，不抢占画布。
2. **卡片掌握度**：三档（未懂 / 模糊 / 掌握），用极低干扰的角标表达（不是彩色边框，不是星星）；由用户手动标记 + 复习结果自动建议。
3. **复习队列**：今日待复习的 5 张卡，右侧面板内翻卡（正面问题/背面答案），两个按钮"还是模糊 / 懂了"；不需要配置、不需要选择。
4. **AI 导师**：带引用的回答（引用可点回原文）、"出题考我"（生成问题卡）、回答可拖成卡片、可对选中的 3 张卡说"帮我找它们的共同前提"。
5. **进度与回顾**：主题进度环（掌握卡 / 总卡）、每周回顾卡（本周新增、连线数、复习正确率、最薄弱的概念）。

**出口标准**：
- 陌生用户不做解释能说出"这个应用会帮我记住东西"（≥ 4/5）；
- AI 回答出现 ≤ 1.5 秒，引用可点击回到原文的对应段落；
- **密度测试**：一屏 40 张卡时，掌握度角标不构成视觉噪音（对比 Stage 5 同场景截图，额外视觉元素占比 ≤ 5%）；
- **增一减一**：相对 Stage 5，屏幕可见文本块数增长 ≤ 10%。

**风险**：加层变成"功能够多"。**对策**：增一减一规则写进评审表；任何新元素必须说明"它替掉了什么"。

## Stage 7 · 组织与检索（体量 M）

**目标**：内容多起来之后，仍然找得到、管得住、批量改得动。

**为什么在这里**：学习空间的自然结果是内容爆炸。没有组织层，前面所有打磨都会被"找不到"抵消。

**关键交付**：
- **Card Library**：网格 / 列表 / 时间线三视图，顶部筛选条（类型、标签、创建者、未分类、自定义），底部数量与批量操作；
- **Tag Database**：表格视图 + 看板视图，属性编辑（文本/数字/单选/多选/日期/复选）、行与列的增删、单元格内编辑、批量填充与撤销；
- **Inbox**：收集 → 分类 → 转成卡片或放进板；跨卡待办聚合；
- **Journal**：周条 + 日期标题 + 待办 + 每日记录；从日志一键"提取成概念卡"；
- **搜索高级筛选**：类型、时间、标签、板、排序。

**出口标准**：
- 1000 张卡下，找到某张特定的卡 ≤ 3 次交互；
- 筛选条件永远可见、可一键清空（不允许"筛完不知道自己在筛什么"）；
- 批量操作（改属性/删除/移动）可一步撤销；
- 表格与看板在同一份数据上切换，状态不丢。

**风险**：表格与看板会吃掉大量时间。**对策**：Tag Database 只做"一屏可演示"的两个视图 + 6 种属性，其余记为"原型未实现"。

## Stage 8 · 打磨与交付（体量 M）

**目标**：从"原型"到"可以交出去的应用"。

**为什么在这里**：收尾要解决的都是"跨界面一致性"问题，只能在所有界面都存在之后做。

**关键交付**：
- **动效统一**：进入/退出/移动三套曲线与时长（150–200ms，`ease-out`），全应用统一；
- **感知性能**：首屏可见内容 < 1 秒；画布操作无掉帧感；大板（150+ 对象）仍跟手；
- **暗色全覆盖**：逐界面走查，不允许"忘了改"的白色斑块；
- **可访问性**：焦点可见、对比度达标（正文 ≥ 4.5:1）、键盘全流程可完成一次学习闭环；
- **状态完整**：空态、加载、错误、超长文本、0 结果、权限不足（示意）；
- **3 条演示脚本**：① 概念学习（读 PDF → 摘卡 → 连成结构 → 问 AI → 明天复习）② 语言复习（今日 5 张卡 → 标记掌握度 → 重新排期）③ 研究写作（多来源 → 分区 → 导出大纲）；
- **交付说明**：如何打开、如何操作、组件索引（每个零件一行：它是什么、用在哪、怎么复用）。

**出口标准**：
- 评分卡平均 ≥ 4.0，关键三项（风格一致 / 连续流 / 学习闭环）≥ 4.5，无单项 < 3；
- 连续 30 分钟真实使用不崩、不卡、不丢状态；
- 陌生用户 5 分钟内独立完成一次"采 → 抓 → 连 → 复"闭环；
- 3 条演示脚本每条都能一次跑通，不需要重来。

**风险**：收尾阶段被"再加一个功能"侵蚀。**对策**：Stage 8 冻结新功能——只允许"修"和"删"。
