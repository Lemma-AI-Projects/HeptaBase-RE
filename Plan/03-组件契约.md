# 03 · 组件契约（C01 – C68）

> 这是"每个组件尽可能低耦合"的可执行版本：**51 个零件，每个只有一件事、只认自己的输入输出、可以被单独替换**。
> 用法：写代码前先查表，确认这个零件的输入输出没有超出本表；超了，说明你要么该拆零件，要么该加一个新零件。

---

## 0. 契约规则（所有零件都遵守）

| # | 规则 | 违反的样子 |
| --- | --- | --- |
| R1 | **只认输入**：零件只根据"我给它的数据 + 它自己的内部状态"渲染，不主动去读全局/兄弟/父级 | 卡片组件自己去问"画布现在缩放多少" |
| R2 | **只发事件**：需要改变外部世界时，只发出"发生了什么"，由外层决定要不要做 | 工具栏直接改写画布里的对象坐标 |
| R3 | **不自带全局样式**：颜色/字号/圆角全部来自基准值（V1–V13），零件内不写死具体数值 | 某个卡片写死 `border-radius: 6px` |
| R4 | **可空可缺**：所有输入都允许缺失，缺失时进入 `空` 或 `禁用` 状态，不报错、不塌陷 | 没传标题就渲染出一个空白方块 |
| R5 | **可被替换**：换掉它的外观或实现，不影响任何其它零件的输入输出 | 换了按钮组件，工具栏的点击事件全失效 |

**判断标准（一句话）**：把它单独放进一个空白页，只给它最小输入——它应该仍然"看起来是对的、点起来是通的"。

## 7. 关键零件的契约细节（最容易写错的 6 个）

### C11 CardNode

```
输入
  card        { id, title, excerpt, color, folded, updatedAt }  必填
  selected    boolean      默认 false
  hovered     boolean      默认 false
  readonly    boolean      默认 false
  mastery     'none' | 'fuzzy' | 'solid'   默认 'none'
  density     'canvas' | 'grid' | 'review' 默认 'canvas'
输出
  selected, opened, editRequested,
  colorChanged(color), folded(bool),
  dragStarted, aiActionClicked(actionId)
禁止
  ✗ 自己读取缩放/视口/所在板信息
  ✗ 内部决定"点一下是打开还是选中"——由外层通过 density 与 readonly 组合出的模式决定
可替换性
  换成"极简卡"（只有标题）时，只需改这一个零件；画布、卡片库、复习卡均不受影响
```

### C10 CanvasViewport

```
输入
  objects     对象集合（各对象自带 type 与几何）
  viewport    { x, y, zoom }  必填
  mode        'edit' | 'readonly'
输出
  objectMoved(ids, delta) / objectResized(id, rect) / viewportChanged(viewport)
  blankDoubleClicked(point) / contextRequested(point, targetIds)
  marqueeFinished(ids, additive)
禁止
  ✗ 直接修改对象的内部数据（只能发事件）
  ✗ 内置任何业务语义（不知道"卡片"和"分区"有什么区别，只按 type 渲染）
可替换性
  换成"表格视图"渲染同一批对象时，上层只处理同一组事件
```

### C30 BlockEditor

```
输入
  blocks      块数组（含类型与内容）  必填
  editable    boolean                默认 false
  width       number（行宽，只影响排版不影响内容）
  caret       { blockId, offset } | null
输出
  blockChanged(id, content) / blockMoved(id, targetIndex) / blockSplit(id, offset)
  blockMerged(id, prevId) / blockFocused(id) / selectionChanged(range)
  slashRequested(point) / mentionRequested(point, query)
禁止
  ✗ 自己决定块的数据结构之外的东西（不能自己保存、不能自己联网）
  ✗ 阅读态与编辑态使用不同的字号/行高
可替换性
  阅读态可以换成一个"纯渲染器"，只要它接受同样的 blocks 数组
```

### C44 AiChatPanel + C45 AiMessage

```
C44 输入
  messages    { id, role, content, citations[], state, draggable }[]
  generating  boolean
  context     { type, id, label }[]      当前已加入的上下文
输出
  messageSent(text) / contextAdded(item) / contextRemoved(id)
  messageDragged(id) / stopGenerating()
禁止
  ✗ 面板自己决定"要不要把这条件放进上下文"——由外层（当前屏幕）决定并传入
C45 输入
  message     见上
输出
  dragged / citationClicked(citation) / savedAsCard() / copied
禁止
  ✗ 消息自己发起"保存为卡"的网络/存储动作，只能发事件
可替换性
  把 AI 消息换成"笔记块"，只要事件名一致，拖拽落地逻辑不动
```

### C51 FilterBar

```
输入
  dimensions  { id, label, options[] }[]    可用维度
  conditions  { dimId, values[] }[]          当前条件
  resultCount number
输出
  filterChanged(conditions) / cleared / savedAsView(name)
禁止
  ✗ 自己过滤数据（只描述条件；过滤由数据层做）
  ✗ 隐藏已生效的条件（条件必须常显，可一键清空）
```

### C63 Popover

```
输入
  anchor      元素引用或坐标   必填
  placement   'auto' | 'top' | 'bottom' | 'left' | 'right'
  content     任意内容
  modal       boolean          默认 false
输出
  dismissed
禁止
  ✗ 内嵌业务逻辑（不知道自己在弹"卡片菜单"还是"颜色选择"）
  ✗ 超出视口（必须自动翻转）
```

## 8. 孤岛测试（每阶段抽 3 个零件执行）

| 步骤 | 做法 | 通过标准 |
| --- | --- | --- |
| 1 | 把零件放进一个空白页面，只给最小输入 | 外观正确、无报错、不塌陷 |
| 2 | 让 5 个人看一眼 | ≥ 4 人认为"它属于这个产品" |
| 3 | 做一次"空/禁用/超长文本"三态抽查 | 三态都有合理表现 |
| 4 | 替换它的外观（换一版样式） | 其它零件需要改动的地方 = 0 |
| 5 | 断开它依赖的输入 | 进入空态而不是崩掉 |

## 9. 新增零件的检查表

要加一个新零件之前，先回答这 6 个问题；有一个答不上来就别加：

1. 它只做一件事吗？（说得出"它负责什么"，且不需要用"和"连接）
2. 它需要的每一条数据都能从外部传入吗？（有没有偷偷去读别处）
3. 它改变外部世界时，是发事件而不是直接改吗？
4. 它的空/禁用/超长 三态长什么样？
5. 它复用了哪些基准值（V1–V13）？有没有写死数值？
6. 换掉它，会影响谁？
