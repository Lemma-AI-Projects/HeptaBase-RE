# Learn Space 原型 · 执行规格书

> 目标：以 HeptaBase 为基座，为 Lemma AI 交付一个**能真正操作**的 Learn Space 高保真原型。
> 优先级：**UI 风格与交互设计 > 功能广度**。｜硬约束：**每个组件尽可能低耦合**。
> 版本：**v2.0**（2026-10-21，按 v1 评审意见重写）｜共 14 屏 / 51 个零件 / 6 个阶段

---

## v1 → v2 改了什么（对照评审意见）

| 评审意见 | v1 的问题 | v2 的处理 |
| --- | --- | --- |
| **颗粒度不够** | 只有原则与路线图，没有一屏一屏的规格 | 新增 **02-逐屏规格**：14 屏，每屏含布局、元素、状态、交互、键盘、**可勾选验收**、因果 |
| **组件低耦合只写了原则** | 没有清单与契约 | 新增 **03-组件契约**：51 个零件逐个写职责 / 输入 / 输出 / 依赖 / 可替换性；6 个易错零件给契约细节；孤岛测试五步 |
| **Stage 划分与范围取舍有问题** | 横向分层（样式→骨架→画布→卡片→学习→组织→打磨），到第 4 阶段才有第一屏能看的 | 改为**设计系统 + 竖切片**（6 阶段），每阶段交付一段可演示的完整动作，且可独立叫停；范围改成 MUST/SHOULD/COULD/WON'T 四档，屏幕数从"没数过"变成 **14 屏明确清单** |
| **验收标准不可执行** | 只有通用评分卡 | 每阶段一份**任务清单 + 验收清单**（全部为可勾选、带阈值的条目）；评分卡降级为总闸门 |
| **因果链太抽象** | 8 条"设计哲学"式链条 | 改成 **K1–K12 落地版**：决定 → 因为 → 否则会怎样 → 落在哪屏 → 指标；并在每屏末尾附一条因果 |
| 产品理解靠假设 | 用 A1–A4 默认值绕过去 | 保留假设但**降到 4 条并集中在 README**，方向依赖最重的两条（内容形态、品牌色）在 Stage 2 第一屏就能被验证 |

## 阶段总表

| 阶段 | 交付 | 屏幕 | 体量 | 停下时它是什么 |
| --- | --- | --- | --- | --- |
| **2** | 设计系统 + 静态白板屏 | S02（只读） | M | 一个能缩放浏览的高保真原型 |
| **3** | 读 → 抓 | S03 S04 S05 | L | 一个能读能记、划线成卡的工具 |
| **4** | 连 → 想 | S02（可交互） | XL | 一个能摆能连能撤销的画布 |
| **5** | 问 → 复 | S01 S06 S07 | L | 一个会帮你记住东西的学习应用 |
| **6** | 找 | S08–S13 | L | 一个内容多起来仍找得到的知识库 |
| **7** | 打磨与交付 | 全部 14 屏 | M | 一个可以交出去的应用 |

**顺序理由**：风格是本次第一优先级（晚做返工最贵）→ 内容层先于交互层（先证明"值得摆"，再打磨"怎么摆"）→ 手感单独成段（黑箱，不能夹着做）→ 差异化放在稳定地基之后（否则像贴纸）。

## 怎么用这份规格书（协作方式）

1. 每阶段结束，我交付**可运行版本 + 2 页说明**（做了什么 / 为什么 / 哪里没做好）；
2. 你只需**打开它用 3 分钟**，然后照 [04-阶段任务与验收.md](04-阶段任务与验收.md) 的验收清单打勾、照 [05-评估标准.md](05-评估标准.md) 打分；
3. 任何一版都可以叫停、改方向；不存在"全部做完才能看"；
4. 有异议优先改 [01-范围与基准.md](01-范围与基准.md)（范围与基准）——改了它，下面的规格与验收跟着改。
