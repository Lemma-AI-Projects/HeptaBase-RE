# 01 · 范围与基准

> 这份文档只回答三件事：**做哪几屏**、**每屏服务于什么**、**什么算"像"**。
> 逐屏怎么写见 [02-逐屏规格.md](02-逐屏规格.md)；零件怎么拼见 [03-组件契约.md](03-组件契约.md)。

---

## 1. 一句话与三个时刻

**Learn Space 是一个"为了理解"的学习空间**：读的、看的、问的、想到的东西都摊在同一个可缩放的平面上，关系自己浮出来；同时系统记得你学到哪一步、哪儿还模糊、什么时候该再看一遍。

所有界面必须归入三个时刻之一，归不进去的就是该砍的界面：

| 时刻 | 用户在做的事 | 成功的样子 | 失败的样子 |
| --- | --- | --- | --- |
| **A 第一次接触** | 把材料变成"我能指着它说话"的对象 | 3 秒看到材料成了卡，知道它来自哪一页 | 上传完一片空白；新内容与已有内容毫无位置关系 |
| **B 整理与理解** | 压卡片、摆结构、问 AI 并留住答案 | 40 分钟没离开这个平面，结构能用一句话说清 | 为整理而不断开面板、跳页；AI 答案看完就丢 |
| **C 回访与巩固** | 5 分钟过一遍该复习的卡 | 不做选择就能开始；做完有"今天够了"的确定感 | 复习变成又一个待办清单，第三次就不打开 |

## 2. 范围取舍（这是 v2 改动的重点之一）

v1 的毛病是"什么都想要一点"——列了 7 个横向阶段，每个阶段都在铺地基，到第 4 个阶段才有第一屏能看的东西。v2 改为**按价值定范围、按竖切片排阶段**。

### 2.1 四类范围

| 类别 | 内容 | 处置 |
| --- | --- | --- |
| **MUST**（不做就没有产品） | 白板画布与对象、卡片编辑器、PDF 阅读与摘录、复习会话、AI 导师面板、今日落点、左栏与标签条、右栏工具面板 + 暗色 | 全部进 Stage 2–5、7 |
| **SHOULD**（做了才像完整应用） | 卡片库、标签数据库、日志、Inbox、全局搜索、命令面板 | Stage 6 |
| **COULD**（有余力才做） | 每周回顾、新建主题流程、小地图、聚焦模式、思维导图 | 穿插在 Stage 5–6，随时可砍 |
| **WON'T**（本次明确不做） | 协作与评论、公开发布、支付、移动端、真实模型调用、PDF/视频真解析、多账号、导入器 | 一律不做，见 §2.3 |

### 2.2 屏幕清单（14 屏，编号贯穿全文档）

| 编号 | 屏幕 | 时刻 | 范围 | 生产阶段 |
| --- | --- | --- | --- | --- |
| S01 | 今日（落点） | C | MUST | Stage 5 |
| S02 | 白板画布 | B | MUST | Stage 2（静态）→ Stage 4（可交互） |
| S03 | 卡片阅读 | B | MUST | Stage 3 |
| S04 | 卡片编辑（编辑器激活） | B | MUST | Stage 3 |
| S05 | PDF 阅读与标注 | A | MUST | Stage 3 |
| S06 | 复习会话 | C | MUST | Stage 5 |
| S07 | 每周回顾 | C | COULD | Stage 5（可延后） |
| S08 | 卡片库 | B | SHOULD | Stage 6 |
| S09 | 标签数据库（表格 / 看板） | B | SHOULD | Stage 6 |
| S10 | 日志 | C | SHOULD | Stage 6 |
| S11 | Inbox | A | SHOULD | Stage 6 |
| S12 | 全局搜索 | B | SHOULD | Stage 6 |
| S13 | 命令面板 | 全局 | MUST | Stage 6 |
| S14 | 新建学习主题（上传 → 解析 → 成板） | A | COULD | Stage 6 |

> **范围纪律**：任何新想法先问"它替换掉清单里的哪一条"。答不上来就不做。

### 2.3 明确不做的四件事与理由

| 不做 | 理由 |
| --- | --- |
| 账号 / 同步 / 协作 / 发布 | 不改变"风格与交互"的任何结论，纯成本 |
| 移动端 | 本次的验收基准是 1440 宽桌面下的密度与手感；手机是另一个设计问题 |
| 真实模型接入 | 模型输出不稳定会污染评审（"刚才那个回答很好"不是设计结论）。用脚本化真实文本 + 引用 + 1.2–1.5s 节奏 |
| PDF / 视频真解析 | 用预置页图与真实排版的占位内容，视觉与交互完全一致，工期差一个数量级 |

## 3. 信息架构

```
Learn Space
├── 左栏上半 · 应用区（C02）
│   ├── 新建学习主题（→ S14）
│   ├── 今日（→ S01）
│   ├── 白板（→ S08 类似列表 → S02）
│   ├── 卡片库（→ S08）
│   ├── 标签（→ S09）
│   ├── 日志（→ S10）
│   ├── Inbox（→ S11）
│   └── 复习（→ S06）
├── 左栏下半 · 标签系统（C03/C04）：普通标签 / 置顶 / 分组 / 文件夹
├── 主区域 · 多面板（C01）
│   ├── 白板 tab（S02）
│   ├── 卡片 tab（S03 / S04）
│   ├── PDF tab（S05）
│   └── 库 tab（S08 / S09 / S10 / S11）
├── 右栏 · 工具面板（C05/C06）：AI 对话 / 卡片库 / 目录 / 信息 / 复习队列 / 回链
└── 全局浮层（C08 之外）：命令面板（S13）、全局搜索（S12）、菜单（C21/C63）、提示（C09/C64）
```

**导航原则**：所有 tab 都在左栏可回溯；白板 ↔ 卡片必须双向跳转且**保留位置**；任何 tab 内容都在主区域内切换，**不做页面级跳转**。

## 4. 六步学习闭环（主演示路径）

| 步 | 动作 | 体验预算 | 成功判据 | 涉及屏 |
| --- | --- | --- | --- | --- |
| 1 采 | 把 PDF / 网页拖进主题 | ≤ 3 秒成卡 | 无上传弹窗焦虑 | S14 → S02 |
| 2 读 | 在原文档划重点 | 划线即出工具条 | 工具条不挡字 | S05 |
| 3 抓 | 划线变成自己的卡 | ≤ 3 次操作 | 自动带出处，可跳回 | S05 → S03/S04 |
| 4 连 | 连两张卡 / 放进分区 | 一次拖拽 | 连线不打架 | S02 |
| 5 问 | 让 AI 解释并留住 | 回答 ≤ 1.5s | 可拖成卡，引用可点 | S02 右栏 → S02 |
| 6 复 | 明天回来复习 | 打开即见 | 不需要配置 | S01 → S06 |

> **红线**：六步之间不允许页面级跳转。一次跳页 = 一次心流断电。

## 5. 阶段划分（v2 重排）

v1 是**横向分层**：样式 → 骨架 → 画布 → 卡片 → 学习层 → 组织 → 打磨。问题是每个阶段都在铺地基，到 Stage 4 才出现第一屏"能看"的东西，而且每层单独看都"没做完"，无法验收。

v2 是**设计系统 + 竖切片**：

| 阶段 | 交付什么 | 为什么这样切 |
| --- | --- | --- |
| **Stage 2** 设计系统 + 静态白板屏 | 全部基础零件 + S02 静态高保真（可缩放浏览，不可编辑） | 风格是本次第一优先级；先让"一屏看起来对"，后面才有参照物 |
| **Stage 3** 「读 → 抓」竖切片 | S03 / S04 / S05：读文档、划线、摘录成卡、写卡 | 这是用户第一次感到"省事"的一段，最能验证内容层是否成立 |
| **Stage 4** 「连 → 想」竖切片 | S02 可交互：拖拽、连线、分区、框选、吸附、撤销、小地图 | 手感是黑箱，必须单独一段连续打磨，不能夹在别的活里 |
| **Stage 5** 「问 → 复」竖切片 | S01 / S06 / S07 + AI 面板：路径条、掌握度、复习队列、带引用回答 | 差异化在此显形；放这里是因为它必须立在稳定的画布与卡片之上 |
| **Stage 6** 「找」竖切片 | S08–S13：卡片库、标签库、日志、Inbox、搜索、命令面板 | 内容变多后才需要；过早做等于给空数据建仓库 |
| **Stage 7** 打磨与交付 | 暗色全覆盖、动效统一、感知性能、空/错态、3 条演示脚本、组件索引 | 收尾问题都是跨屏一致性，只能最后做 |

**每个阶段的共同要求**：结束时**能演示一段完整动作**（见 [04-阶段任务与验收.md](04-阶段任务与验收.md) 的"演示脚本"），并且**可以独立叫停**——停下时它仍是一个能打开、能点的东西。

## 6. 关键因果链（落地版：决定 → 屏幕 → 指标）

v1 的因果链被批评"像设计哲学"。这一版每条都绑定到具体屏幕与可测指标。

| # | 决定 | 因为 | 否则会怎样 | 落在哪屏 | 指标 |
| --- | --- | --- | --- | --- | --- |
| K1 | 打开应用落在"今日"，不落在空白画布 | 空白画布在 5 秒内传递的信息是"这里什么都没有" | 首次进入即离开 | S01 | 5 秒定位测试 ≥ 4/5 |
| K2 | 卡片唯一、白板只引用 | 卡片若被钉死在板里，用户会复制粘贴，知识分裂成互相矛盾的副本 | 同一概念两处不一致 | S02 / S03 | 同卡在两块板改一处两处同步 = 100% |
| K3 | AI 回答可拖成卡、带引用 | 停在对话框里的答案不会被复习、被连线 | AI 永远只是"查一下" | S02 右栏 | 从提问到成卡 ≤ 2 次操作；引用可点回原文 |
| K4 | 划词工具条浮在选区上方、不遮挡 | 工具条盖住文字，用户就得先取消选择再读 | 读-抓被打断 | S05 | 划线到成卡 ≤ 3 次操作 |
| K5 | 画布吸附"一次到位"，不做二次微调 | 差 2px 的摆放会让整块板看起来潦草 | 用户不敢摆乱，退回列表 | S02 | 摆放后无手动微调比例 ≥ 90% |
| K6 | 一切破坏性动作一步撤销 | 没有撤销，用户只会把东西摆得整整齐齐 | 空间范式失效 | S02 / S09 | 破坏性动作撤销覆盖 = 100% |
| K7 | 复习入口不要求配置、不要求选择 | 任何"先选范围"的步骤都会让人第三次就不打开 | 记忆层死掉 | S01 / S06 | 3 次回访后仍继续使用 ≥ 4/5 |
| K8 | 掌握度只用极低干扰角标 | 彩色边框/星级会在 40 张卡时变成噪音 | 板子变吵，看不清内容 | S02 / S06 | 密度测试：额外视觉元素占比 ≤ 5% |
| K9 | 学习路径条可折叠成一条线 | 常驻的进度条会抢占画布上部空间 | 画布被 UI 压缩 | S01 / S02 | 折叠后占高 ≤ 28px |
| K10 | 左栏"应用区 + 标签区"两段式 | 应用是"去哪"，标签是"刚才在哪"，混在一起会互相干扰 | 找不到刚打开的板 | S02 左栏 | 找回上次 tab ≤ 2 次交互 |
| K11 | 命令面板与全局搜索分开（⌘K / ⌘O） | 一个是"做事"，一个是"找东西"，混用会让两者都变慢 | 找卡时看到一堆命令 | S13 / S12 | 目标卡 ≤ 3 次交互 |
| K12 | 暗色不是反色，是重设明度关系 | 深色下阴影不可见，卡片会失去层次 | 暗色像"套了个滤镜" | 全屏 | 暗色下层次辨识 ≥ 90% |

## 7. 视觉指纹（13 条，判"像不像"）

数值为读图估计，Stage 2 固化为唯一来源；**容差外即失败**。

| # | 项目 | 基准 | 为什么（感知后果） | 容差 |
| --- | --- | --- | --- | --- |
| V1 | 画布底色 | 暖灰近白（约 `#F7F7F4`） | 让白卡"浮起来"；纯白底让卡片失去存在感 | ±3% 明度 |
| V2 | 卡片本体 | 纯白 + 1px 极浅描边 + 极淡阴影 | 层次靠描边不靠重阴影，才有"纸上贴纸"的轻 | 阴影 ≤ 8% 不透明、模糊 ≤ 6px |
| V3 | 圆角 | 卡片 8 / 浮层 10–12 / 胶囊全圆 | 亲和但不软塌；更大圆角变"玩具感" | ±2px |
| V4 | 正文排版 | 13–14px / 行高 1.6 / 字重 400 | 密度与可读的平衡点 | 字号固定 13–14 |
| V5 | 界面文字 | 12–13px，次要信息 55–65% 灰 | 界面退后，内容上前 | — |
| V6 | 强调色 | 单一蓝（约 `#3B82F6`），只用于"当前/选中/今天" | 一屏最多 1–2 处，否则失去指示性 | 每屏 ≤ 3 处 |
| V7 | 卡片色板 | 低饱和粉彩（绿/蓝/橙/紫/红/黄/灰），**整卡浅底色 + 分区实色胶囊**（按 references 里的参考图更正） | 颜色用来分类不用来装饰；正文永远黑字 | 饱和度 ≤ 35% |
| V8 | 分区 | 上边缘一条**实色胶囊 + 白字**，下方分区底色比卡片更浅 | 让"组"一眼可辨，不必画边框 | — |
| V9 | 图标 | 线性、1.5px、灰度、20px 网格 | 彩色只留给内容（应用图标是唯一例外） | 不混用彩色图标 |
| V10 | 浮层 | 白底 + 圆角 + 极淡阴影 + 8px 内边距 | 浮层是临时工具，不能抢内容 | 永不遮挡视口中心 |
| V11 | 布局 | 左栏 240 / 右栏 360 / 画布无限，两侧可收 | 三栏 = 目录—内容—工具的心智模型 | ±40px |
| V12 | 留白节奏 | 卡内密（8–12px）、卡间松（≥ 24px） | "外松内密"是密度感来源；反过来又空又乱 | — |
| V13 | 动效 | 150–200ms、`ease-out`、只有出现/消失/移动三类 | 超 250ms 就变成等待 | ≤ 250ms |

| # | 指纹 | 表现 | 为什么 | 主要落在 |

## 9. 组件低耦合（可验证版）

三条可执行规则，每一条都有对应的验收动作：

| 规则 | 含义 | 验收动作 |
| --- | --- | --- |
| **单一职责** | 一个零件只回答一个问题（卡片承载内容、分区圈定范围、连线表达关系） | 说清"它负责什么"，说不清就拆 |
| **契约输入输出** | 只通过"给它什么 / 它会告诉你什么"沟通，不偷读别处状态 | 单独放进空白页仍正常工作（孤岛测试） |
| **替换不连带** | 换掉一个零件的外观或实现，其它零件不需要改 | 随机换 1 个零件的样式，连带改动 = 0 |

具体到 51 个零件的职责、输入、输出、依赖，见 [03-组件契约.md](03-组件契约.md)。
